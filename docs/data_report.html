Recall Match: how the data flows

Generated by python -m app.data.report from data/raw, data/nhtsa.db and the stored runs in data/app.db. Static snapshot: no model or server needed to view it (the diagrams load mermaid from a CDN; offline they show as text, also in docs/DATA_MODEL.md).

One complaint flows left to right. Only judge calls a model; everything else is code, so every number and every recall shown comes from the data, not from the AI. The AI proposes; verify checks every quote word for word and decide sets the outcome by rules. If the answer fails verification twice, decide falls back to a labelled rules-only answer.

Complaints received 2020-01-01 to 2026-11-17; recalls filed 2010-01-01 to 2026-11-16. The app opens it read-only. Analyst work and AI runs live in a separate file (data/app.db, section 5).
